# 第一版范围与发布门槛

目标：其他人在自己的电脑上可以安装、记录、重启后读回，并通过备份恢复；不需要作者的私人工作区。

架构：Next.js / React 前端与本地 API；单个 JSON 主账本、原子替换、修订号、完整历史版本；可选 Python Codex 索引。主数据与代码分离。仅支持单服务进程、单用户。

不含：公网上线、账户系统、多人协作、iPhone 客户端、实时同步、NAS 自动备份、作者私人自动化或历史迁移执行脚本。

仓库由应用源文件白名单建立全新历史；不复制真实记录、截图、会话、memory、分析快照、运行日志或旧 Git 历史。测试使用虚构人物和项目；私有安装规则在独立配置中，默认关闭。

## 门槛

- 干净 `npm ci`，锁文件可重现。
- 源码入口 `node tools/start.mjs` 完成首次安装与启动；再次启动复用构建，更新后显式使用 `--rebuild`。不得自动切换数据目录或后台更新代码。
- 单元测试、类型检查、生产构建通过。
- 临时账本跑通保存、并行、修改隔离、冲突拒绝、重启保留、版本恢复、导出格式的新安装恢复。
- 私密信息扫描和第三方依赖清单复核。
- GitHub Actions CI；源码发布前复核文档、权限范围和截图。
- 一位新用户按 README 实际试用，记录遇到的障碍；技术测试不代替真实使用反馈。

## 隐私检查

示例和测试必须使用专门构造的数据。只换人物姓名不够：真实书目、项目、餐食、运动组合、家庭时间表也不能原样复制。人工复核所有 fixtures 和测试中的具体名称、数值与日期来源；不将“扫描通过”表述为“绝对没有个人信息”。

上传前运行 `node tools/check-release.mjs --staged --history`，同时检查暂存文件与所有本地引用可达的历史。CI 使用完整历史运行同一检查。可追加 `--deny-file /absolute/path/outside-checkout.json` 指定本机 JSON 字符串数组，以核对私人上下文；该文件必须在代码目录之外，不上传词表，也不把真实账本输入测试。扫描只报告文件和类型，不输出命中的原文。

历史脱敏需要协调所有分支和副本，使用明确的 force-with-lease 避免覆盖新提交。普通修复提交不会删除旧版本。GitHub 的旧 PR 引用和缓存可能仍保留内容，必要时由仓库所有者联系 GitHub Support；未完成前不能宣称平台侧彻底清除。
