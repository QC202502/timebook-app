# 保存、升级与恢复

## 本机保存

新安装从空账本开始。保存使用修订号防止旧页面覆盖新数据，并用操作 ID 避免重复写入。文件先写到临时文件并同步，再原子替换；每次保存保留可校验的历史版本。文件损坏时拒绝读取或覆盖，不静默重置为空账本。

不要同时启动两个进程共用一个数据目录。当前写入队列仅在单进程内有效，不是分布式锁。

可选环境变量（绝对路径）：

- `TIME_LEDGER_HOME`：主数据目录。
- `TIME_LEDGER_DATA_FILE`：单独指定主账本路径；未指定辅助目录时，版本和操作日志跟随这个文件隔离。
- `TIME_LEDGER_PROTECTION_DIR`：历史版本目录。
- `TIME_LEDGER_USAGE_FILE`：明确开启后使用的本地操作日志文件。

## 找回误删或误改

打开“数据安全”，选择历史版本和要恢复的记录，预览差异后确认。单条恢复保留其他后续记录。整本恢复会替换当前分类、关联与记录，但先永久保存恢复前版本。如果预览后有新修改，需要重新预览。

版本库和主文件在同一电脑上，不能应对整机损坏。不要把版本库放进 Git。

## 在新电脑恢复导出的 JSON

先把备份文件安全复制到新电脑，安装本项目。在 `web/` 内运行：

```bash
node tools/import-backup.mjs /absolute/backup.json /absolute/new-ledger-directory
TIME_LEDGER_HOME=/absolute/new-ledger-directory npm start
```

目标目录必须不存在；工具会校验格式、分类、关联及并行限制，拒绝覆盖已有目录和导入示例备份。支持当前 version 3 全量 JSON。成功后检查日期、记录数和分类，再开始使用。原备份文件不会改动。

Codex 扩展的用户更正和索引不包含在顶部账本备份内；在 Codex 页单独备份更正。来源会话文件也需要自己保存。

## 升级

1. 导出当前 JSON 并另存一份；记下数据目录。
2. 停止当前服务，安装新版本依赖并构建。
3. 使用原 `TIME_LEDGER_HOME` 启动，核对原记录。

不要自动执行来自作者个人环境的历史迁移脚本；本发行包不携带此类执行脚本。未来结构变更必须提供兼容说明、备份和恢复验证。
